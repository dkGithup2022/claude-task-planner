페르소나

본문

최소 스펙부터, 꼭 필요한 스펙만 나열한다. 기존 구조에 테이블을 추가한다면 기존 DB 를 먼저 조회해 컨벤션을 파악한다.

덧붙임 1

원격 회고는 처음 5분을 각자 조용히 의견을 적는 시간으로 둔다. 이 시간이 없으면 말 많은 사람의 의견만 남는다.

덧붙임 2
  1. FK 제약은 걸지 않는다. 참조 컬럼은 가능하면 <테이블>_id 이름의 키 값으로 두어 xx.id = yy.xx_id 형태로 잇는다.
  2. 한 테이블에서 특정 역할의 컬럼이 많아지면 의미 단위로 묶어 별도 테이블로 나누고, 원래 테이블의 id로 잇는다.
article {
  id
  title
  ...
}

article_popularity {
  id
  article_id   -- article.id 를 가리키지만 FK 는 걸지 않는다
  views
  likes
  dislikes
  followed
}
덧붙임 3

한 테이블에서 특정 역할을 하는 컬럼이 많아지면 그 컬럼들을 의미 단위로 별도 테이블로 나눈다. 예: article 의 인기도 지표 컬럼(views, likes, dislikes 등)이 많으면 article_id 를 가진 article_popularity 테이블로 나눈다.

근거

그리고 원격 회고는 처음 5분을 각자 조용히 의견을 적는 시간으로 둬야 해, 안 그러면 말 많은 사람 의견만 남아.계획 3 (서버에 없음)
