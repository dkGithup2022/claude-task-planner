# plan-run 스킬: 고치는 사람을 위한 맥락

SKILL.md 는 스킬을 부를 때 세션 컨텍스트에 그대로 들어가므로, 맥락 설명은 이 파일에 둔다. 계획서: specs/plans/workflow-plan_run.md 묶음 5-3.

- plan-go 스킬과 같은 모양이다. 다른 곳은 세 군데다.
  1. 명령을 백그라운드, 제한 시간 70분으로 부른다.
     노드는 메인 세션이 띄우지 않는다. task-planner 명령 안에서 우리 코드(run_agent)가 claude -p 로 실행한다.
     그래서 명령 하나가 30분 차례 하나(마지막 노드까지 최대 60분)를 돈다.
     Bash 의 기본 제한 10분을 넘으므로 백그라운드로 부르고 timeout 을 70분으로 준다.
  2. Stop 훅 안내 한 줄.
     start 가 작업 지시 견적을 곧바로 돌려주면 백그라운드 명령이 금방 끝난다.
     그 뒤 세션이 턴을 끝내려 하면, 훅이 next 를 부르라고 막는다 (engine/hook/stop_hook.py).
     2026-11-20 일괄 시험에서 세 번 모두 일어났고, 한 번은 세션이 앞 출력을 읽기 전에 next 를 불렀다.
  3. finished 의 글을 그대로 보인다. 끝 알림(notify)의 노드별 표가 들어 있다.
- spawn 줄은 이 흐름에서 쓰이지 않는다. engine 의 SUBAGENT 단계가 없기 때문이다.
  plan-go 와 글을 맞추고, 나중에 SUBAGENT 단계를 넣어도 스킬을 고치지 않으려고 둔다.
